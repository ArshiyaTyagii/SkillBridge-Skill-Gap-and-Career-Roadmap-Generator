# Contributing to SkillBridge

Thank you for your interest in contributing to SkillBridge.

## Before you begin

1. Check the existing issues and pull requests to avoid duplicating work.
2. For substantial changes, open an issue to discuss the proposed approach.
3. Do not commit passwords, API keys, database credentials, personal resumes, or other private data.

## Development workflow

1. Fork the repository.
2. Create a feature branch:
   ```bash
   git checkout -b feature/your-feature-name
   ```
3. Make focused changes that follow the existing project structure and coding conventions.
4. Add or update tests for changed functionality.
5. Run the relevant tests and checks.
6. Commit your changes with a clear message.
7. Push your branch and open a pull request.

## Pull request checklist

- [ ] The change has a clear description.
- [ ] Relevant tests have been added or updated.
- [ ] Existing tests pass.
- [ ] Documentation has been updated where necessary.
- [ ] No secrets, generated build files, or personal data are included.

## Code quality

- Prefer small, modular functions and meaningful names.
- Keep C++ interfaces and implementations organized.
- Handle invalid input and errors explicitly.
- Avoid adding dependencies unless they are necessary.
- Document non-obvious algorithmic decisions.

By contributing, you agree that your contributions may be distributed under the project's license.
